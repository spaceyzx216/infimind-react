## 2. 关键约束（改之前先读）

### ⚠️ PM2 必须保持单实例

`ecosystem.config.cjs` 是 `instances: 1` + `exec_mode: 'fork'`，**不要改成 cluster**。
后端有进程内状态：**会话材料存储**（追问时靠它取回此前上传的合同）、向量索引缓存、SiliconFlow 降级计数。
多实例后追问请求可能落到另一个 worker → 附件记忆间歇性失效，极难排查。

### ⚠️ 前端必须在本地构建

服务器上是**后端为主**的部署（`src/` 有，但没有 `vite` 等 devDependencies，也没有 `vite.config.js` / `public/`）。
**不要试图在服务器上 `npm run build`** —— 会失败。本地构建后上传 `dist/`。

### ⚠️ 依赖不需要重装（通常）

服务器 `node_modules`（261M）与本地依赖清单**完全一致**（`better-sqlite3@12.11.1`、Node ABI 137）。
直接复用即可，**不要随便 `npm install`** —— `better-sqlite3` 是原生模块，重装有失败风险。

### ⚠️ Nginx 的 SSE 配置已经是对的

`www.flylegal.cn.conf` 里 `/api/` 反代已有：

```nginx
proxy_pass http://127.0.0.1:8790;
proxy_buffering off;
proxy_read_timeout 3600s;
proxy_send_timeout 3600s;
```

`proxy_read_timeout 3600s` 尤其重要 —— 深度思考档实测要 **168 秒**，nginx 默认 60s 会掐断。

## 3. 标准更新流程

### 步骤 1｜本地构建

```bash
cd <本地项目目录>
rm -rf dist && npm run build
# 确认产物包含最新改动（用特征字符串，不要只看时间戳）
grep -q "正在思考" dist/js/index-*.js && echo "✅ 思考面板已打包"
```

### 步骤 2｜备份服务器

```bash
ssh root@81.68.223.9
TS=$(date +%Y%m%d-%H%M%S); BK=/www/backup/infimind-$TS; mkdir -p $BK
R=/www/wwwroot/www.flylegal.cn

tar -czf $BK/agent-api-v2-code.tar.gz --exclude='node_modules' -C $R agent-api-v2
```

### 步骤 3｜打包并上传

> ⚠️ macOS 打包会给文件加扩展属性，服务器 tar 会刷一屏 `Ignoring unknown extended header keyword` 警告。**无害，可忽略**；想避免就加 `COPYFILE_DISABLE=1`。

```bash

tar -czf /tmp/deploy-backend.tar.gz \
  --exclude='server/knowledge-base/templates.db' \
  --exclude='server/knowledge-base/labor-kb-labels.json' \
  server src package.json package-lock.json ecosystem.config.cjs \
  docker-compose.rag.yml .env.example

scp /tmp/deploy-backend.tar.gz /tmp/deploy-dist.tar.gz root@81.68.223.9:/tmp/
```

> 排除 `templates.db` 是因为它与服务器上的完全相同（10,285,056 字节，sha256 `54e86c75…`），传了也是白传。
> **若合同知识库有更新，则必须一并上传。**

### 步骤 4｜在服务器上解压

```bash

grep -o '/js/index-[^"]*\.js' $R/dist/index.html           # 应指向新入口
```

## 4. Qdrant 运维

```bash
cd /www/wwwroot/www.flylegal.cn/agent-api-v2

# 状态
docker ps --filter name=infimind-contract-rag
curl -s http://127.0.0.1:6333/collections/contract_knowledge_evidence

# 启动 / 停止（数据卷保留）
docker compose -f docker-compose.rag.yml up -d
docker compose -f docker-compose.rag.yml down

# 重新灌向量（幂等；换 embedding 模型后必须做）
npm run sync:contract-embeddings -- --status   # 先只读确认
npm run sync:contract-embeddings               # 2057 条，实测 16.4s
npm run sync:contract-embeddings -- --rebuild  # 先删 collection 再重建
```

> ⚠️ **不要用 `npm run import:templates` 灌向量** —— 它会先 `resetKnowledgeBase()` 全量重建，
> 源目录不完整就丢数据。这就是专门有 `sync:contract-embeddings` 的原因。

> 🔒 Qdrant **无鉴权**，端口在 compose 里写成 `127.0.0.1:6333:6333`。**不要改成 `6333:6333`**，
> 也不要在宝塔「安全」里放行 6333。

### 已知故障：Docker socket 会消失

**症状**：`docker info` 报 `dial unix /var/run/docker.sock: connect: no such file or directory`，
但 `systemctl is-active docker` 显示 active，`ss -lx` 还能看到 `/run/docker.sock` 在监听。

**根因**：dockerd 用的是 `-H fd://`（systemd **socket 激活**）——socket 由 `docker.socket` 这个 unit 创建并传入。
若 socket 文件被删除，守护进程仍持有失效 fd，**只重启 `docker.service` 没用**。

**修复**（两个 unit 都要重启，顺序重要）：

```bash
systemctl stop docker.service docker.socket
rm -f /run/docker.sock /run/docker.pid
systemctl start docker.socket
systemctl start docker.service
docker info    # 应正常返回
```

若容器启动时报 `failed to create TTRPC connection ... connection refused`，是 containerd 侧同样的问题：

```bash
systemctl stop docker.service docker.socket
systemctl restart containerd
systemctl start docker.socket && systemctl start docker.service
# 清理失败容器与僵尸 shim
docker rm -f infimind-contract-rag
pkill -f "containerd-shim-runc-v2.*containerd.runc.v1.Options"
```

## 5. 环境变量（`/www/wwwroot/www.flylegal.cn/agent-api-v2/.env.local`）

**必须正确的几项**：

| 键 | 值 | 说明 |
| --- | --- | --- |
| `LOCAL_SERVER_PORT` | `8790` | nginx 反代的目标端口，改动需同步改 nginx |
| `DEEPSEEK_FLASH_MODEL` | `deepseek-flash` | **官方名**。曾写别名 `deepseek-v4-flash`（能用但未文档化） |
| `RAG_EMBEDDING_MODEL` | `Pro/BAAI/bge-m3` | ⚠️ **必须与 `labor.db` 内的向量模型一致**，否则语义召回降级为纯词法 |
| `RAG_EMBEDDING_URL` | `https://api.siliconflow.cn/v1/embeddings` | |
| `RAG_RERANKER_MODE` | `siliconflow` | 设成 `heuristic` 会退回启发式重排，**检索质量明显下降** |
| `RAG_RERANKER_URL` | `https://api.siliconflow.cn/v1/rerank` | |
| `RAG_VECTOR_URL` | `http://127.0.0.1:6333` | 留空 = 关闭合同向量路 |
| `RAG_VECTOR_COLLECTION` | `contract_knowledge_evidence` | 与 `sync:contract-embeddings` 一致 |

> 历史情况：2026-09-20 之前的配置里 `RAG_VECTOR_URL` 是**空的**、`RAG_RERANKER_MODE=heuristic`，
> 注释写着「初次部署使用本地 SQLite 全文知识库，不依赖 Qdrant 或 SiliconFlow」——
> 那是刻意的精简配置，但**用工咨询的检索质量（precision@1 50%→66.7%）正是靠模型重排换来的**。

可用只读方式核对（不显示密钥值）：

```bash
E=/www/wwwroot/www.flylegal.cn/agent-api-v2/.env.local
grep -E '^(LOCAL_SERVER_PORT|DEEPSEEK_FLASH_MODEL|RAG_[A-Z_]+)=' $E
```

## 6. 回滚

```bash
BK=$(ls -d /www/backup/infimind-* | tail -1)
R=/www/wwwroot/www.flylegal.cn

# 代码
cd $R/agent-api-v2 && tar -xzf $BK/agent-api-v2-code.tar.gz --strip-components=1

# 前端（旧目录仍保留在 dist-old-<时间戳>）
cd $R && rm -rf dist && mv $(ls -d dist-old-* | tail -1) dist

# 环境变量
cp $BK/env.local.bak $R/agent-api-v2/.env.local

# nginx
cp $BK/www.flylegal.cn.conf /www/server/panel/vhost/nginx/ && nginx -t && nginx -s reload

pm2 reload infimind-server
```

Qdrant 停掉**不影响用工咨询主链路**（它的向量存在 `labor.db` 内，不依赖 Qdrant）。
此时合同知识库的语义召回会降级为词法，但**会明确告警**（`warnings` 里出现「合同知识库语义召回（…）已降级」），不会静默失效。
