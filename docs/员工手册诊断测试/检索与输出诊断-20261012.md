# 员工手册检索与输出诊断（2026-10-12）

## 结论

当前不足同时存在于检索、上下文组织、归并和建议质量，不能用增加向量检索解决所有问题。本轮先修复实际观察到的漏召回和排序问题，增加可核查的输出门禁；保留正文逐块检查，没有接入向量服务、增加依赖或改变用户接口。后续可针对尚未补词的语义遗漏做向量／混合召回对比。

采用10个场景的最终及复验记录，逐项查看18项输出：14项与预设问题方向一致，另外4项作为独立法律疑点待复核。没有将待定事项算成正确或错误，没有发布生成精确率或法律准确率。修改稿与问题识别分开审阅，不能因为检出了问题就认定修改稿可直接采用。

## 如何归因

| 证据 | 归因与处理 |
|---|---|
| R22工资日期原文都已提取、各自分块完整，但“发薪／薪金”没有建立正文关联 | 补主题表述；保留原分块，不把漏召回误当成分块丢失 |
| 关联已经存在，逐块审查的前两段context被封面背景占满，模型只能看到另一条规则的索引摘要 | 对上下文按具体措辞与主题排序，再选前2块；索引摘要仍只供导航 |
| 参考库里有法定节假日规则，但只按大主题排序优先取到工作日／休息日规则 | 中文双字词项、词项稀有度及标题匹配排序，仍选前2块；没有冒称BM25或向量检索 |
| 正确相关原文已输入，模型只在supersedesFindingIds列出部分旧冲突，留下重复结果 | 提示每项旧冲突都须明确保留或声明替代，并检查处置覆盖；不靠相似度删除独立问题 |
| 旧T18修改稿概括为“补休或支付加班工资”，没有区分加班类型 | 提示保留工作日、休息日及法定节假日条件；新稿已区分类型，具体条文和适用性仍待核验 |

定位依据是提取正文、分块位置、实际模型请求、响应与检查点，不能仅凭最终页面推测哪个环节出了错。保持材料和模型模式一致，R22另跑“仅检索改动”与“仅提示词改动”两份隔离代码：前者检出有双方引文支持的发薪冲突，后者仍未召回双方、没有生成已定位冲突。这是一个样例的归因证据，不是大样本因果结论。

原件漏字、行列错位等解析问题没有在这组文本评测中复现，未因此重写解析或分块算法。边界中仍有新表述遗漏，不将补词等同于解决语义召回。

## 检索指标

标注由本轮助手逐对审阅虚构原文完成，**不是独立法务金标**。13个规则场景包含11个调优样例、2个补词后新增且未继续调优的困难边界；后者不是严格盲测或生产分布。相关规则对包括同一事项约束、定义和例外，不仅限于最终冲突。两段正文的标签与原文对应，背景块另计，不静默把它们判成不相关。

每个参考查询标注1个直接回答规则，Precision@2分母固定为2，即这组标注的最高值为50%；不能据此认定一半模型结论错误。追问未另行改排序算法，未包装成一次性能提升。规则候选的“报到／上岗”“收入／酬劳”两个困难变体仍漏召回，没有为了提高数字继续往词表填入这两组答案。所有比例仅适用于本套小样本。

## 输出防护：真实失败与构造反例分开

- **真实失败回归**：上下文已召回却没进入review，先写失败测试再改排序；归并遗漏旧ID处置，测试须失败，明确保留独立冲突应成功。归并只验证每个旧ID被处置，仍不能自动证明模型合并判断正确。
- **预防性反例**：非冲突修改稿未经确认改变原文明示时点时暂不提供该示例；逐块finding不能只引用context，错误归属仅纠正一次，仍错误则保留已完成单元并停止。旧缓存若引用归属不合要求不会直接放行。
- **证据纠正**：本轮曾将R21处理顺序误当成上传顺序，完整逐调用核对后确认该真实用例没有时点漂移或引用错块。上述两项只计构造反例加固，不能宣称它们修复了R21的真实错误；最后恢复没有为此重新调用模型。保留测试失败和检查记录，不据误读继续修改该样例。

这些检查是结构与事实防护，不能自动证明法律适用、解释和建议准确；不为法律缺口输出“已核验”状态。
