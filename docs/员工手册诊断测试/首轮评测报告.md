# 员工手册真实链路评测（2026-10-11）

本轮已交付19组虚构测试用例，并通过真实模型测试修正脱敏、冲突归并和关联完成确认问题。预设21个阳性观察点均有对应诊断结果；这表示本批合成用例的观察点覆盖，不是“法律准确率100%”，也没有完成法务验收。

## 测试究竟走了什么

17组通过真实HTTP登录、认证、上传、文件保存、任务数据库、本地队列、任务处理器、原生解析和DeepSeek模型；没有替换模型响应。T11与T15为两组原生解析覆盖实验，不计作完整HTTP诊断通过。T08另外检查报告追问与SSE回放；T14另外检查明确部分读取后的恢复；T03/T08/T12通过HTTP restart复用真实检查点并重新核对关联。

模型为运行代码配置的deepseek-flash，默认思考模式；原始请求、响应、tokens和事件均存于各次运行目录。测试账号、数据库及上传目录独立隔离，本地5173/8789运行服务未停止。旧公司手册、新法务材料、现役数据库和内部知识库没有发送到模型。本轮参考资料与法规元数据基线均为空，不能据此评价现役知识库召回或具体法条核验效果。

长手册六章，原稿42,387字符，Word提取正文42,679字符（包含标题与段落空行），渲染53页。它用大量重复资料流转条款制造干扰，在中段加入普通辞职违约金，首尾放入补正期限和旷工认定矛盾。它是可重复的压力材料，不代表自然写作的所有长手册。

最终长文结果由原有逐块检查点加修复后的真实关联恢复组成，没有再从零重复整本长文。完整运行和恢复分别计时，不把恢复的66秒宣传为整本新诊断耗时。测试同时还有独立的短文运行，单个任务队列并发为1；这些测量不能外推生产并发或延迟承诺。

## 查到并修正的代码问题

1. 原合同脱敏正则把“员工怀孕后公司”“从考勤异常通知……通过公司”误认为不同实名单位，吞掉条件和期限，制造主体冲突。员工手册现在使用专门的名称识别，仍复用直接身份标识脱敏；公共合同脱敏逻辑未修改。新增回归先复现失败，再修复通过。
2. 模型有时用对象形式返回已核对关联，之前任务直接失败。现在兼容字符串ID及明确checked:true对象；false、遗漏或错误ID仍不能完成检查。
3. 原文错误的冲突草稿不能被后续正确引文替换，且后续关联批次会收到仅部分来源在本批内的旧问题。现在仅提供完整来源属于本批的已有问题，模型明确归并且新引文唯一核验时可替换同来源错误草稿；不同来源和独立条款仍不能被吞掉。
4. 提示词明确范围细化、例外或补充不当然矛盾，压制仅因为简短、未写所有操作细节就制造问题。缓存指纹包含实际发送的脱敏输入和提示词，规则或脱敏变化不会复用旧输出。

## 已确认的限制

- T11原生Word表格文字被提取，但内嵌图片条款遗漏；T15有文字层的同页PDF也遗漏图片条款。当前支持文件格式，但复杂内容读取覆盖不完整。这是已知失败，不能把“解析成功”包装为“全文读完”。
- T17纯扫描PDF走通真实OCR和模型，但“忘打卡”被识别为“半打卡”；OCR返回83置信度仍可能错字。运行还出现语言加载告警，随后返回可读中文，尚未定位告警根因。图片、扫描输入需保留识别核对步骤。
- T19正常对照仍出现两项依赖“其他制度引用”“系统可能关闭”等未提供事实的待核实建议。虚假单位冲突已消除，过度建议尚未完全校准；没有将它们当作已确认法律风险。
- T09首轮将访客说明视为无关材料而拦住整组，后续复测将它作为相关附件放行；范围识别存在模型波动。两次均没有判员工九时与访客十时为同一劳动制度冲突。
- 没有完整的具体法律条文核验：法规名称、版本、来源命中不等于某个条文内容与适用条件正确。程序事项是核对清单，没有审查真实讨论、公示、签收证据；新法务文件仍未提供。
